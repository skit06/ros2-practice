ROS 2 上位机（Qt 界面）笔记
—— 必须背下来 vs 只要看懂
一、必须背下来的内容（硬规则与工程模板）
这部分是开发 ROS 2 上位机时的核心底线与肌肉记忆，必须烂熟于心：
1. Qt 窗口生命周期的四步骨架
任何 Qt 桌面界面的启动与存活都严格遵守这四行顺序：
app = QApplication(sys.argv)：第一句必须初始化大管家，接管系统事件（键盘、鼠标、窗口调度）。
label = QLabel()：创建 UI 控件实例。
label.show()：所有 Qt 控件创建后默认都是隐藏状态，必须显式调用展示才会渲染弹窗。
sys.exit(app.exec_())：启动 Qt 主事件循环并死循环阻塞；一旦缺少这行，代码执行完后会直接闪退。
2. ROS 2 与 Qt 结合的多线程固定模板（死循环解冲）
冲突本质：Qt 的 app.exec_() 和 ROS 2 的 rclpy.spin() 都是死循环，放在同一个单线程里会导致后一个永远无法运行。
固定解法：主线程专供 Qt 跑界面，另开子线程挂载 ROS 2 监听。
# 这一段属于 100% 固定模板，只要做界面必须直接套用：
spin_thread = threading.Thread(
    target=rclpy.spin, args=(node,), daemon=True
)
spin_thread.start()
必须写死的细节：
target=rclpy.spin：子线程的执行目标永远是 ROS 旋转监听。
args=(node,)：末尾的逗号 , 是 Python 元组语法，漏掉会报语法错误。
daemon=True：必须设为守护线程，确保主窗口关闭时后台监听线程自动自杀，防止进程在后台假死残留。
3. 回调函数的参数铁律
只有 (self)：定时器回调（timer_callback）。纯时间触发，系统没有塞给你数据包裹。
必须写 (self, msg)：话题订阅回调（status_callback）。DDS 通信底层强行把接收到的数据包送过来，必须留一个变量位 msg 接住，否则运行时直接报参数数量不匹配崩溃。
4. UI 文字刷新的唯一直接指令
self.label.setText(新字符串)：上位机界面刷新的核心动作永远只有这一步。收到新数据后，用字符串拼接好内容，调用 setText() 覆盖旧字，Qt 会自动触发重绘。
二、只要看懂的内容（底层机制与随查工具）
这部分属于底层运行逻辑或可查阅的工具语法，看懂原理即可，不需要花时间死记硬背：
1. 为什么一个独立的 QLabel 就能当窗口？
Qt 的底层渲染规则：任何控件只要没有指定父级容器（Parent），系统就会自动为它加上操作系统的标准边框、标题栏和关闭按钮，将其视为一个独立的顶级桌面窗口。
2. 代码里的冒号类型标注（Type Hint）
形如 def __init__(self, label: QLabel): 或 status_callback(self, msg: SystemStatus): 中的 : QLabel 和 : SystemStatus，只是给 IDE（如 VS Code）看的便签。
它在运行时没有任何语法强制约束，去掉也不会报错，主要作用是在你敲代码时让编辑器能准确弹出属性补全（如提示 .cpu_percent）。
3. 字符串排版格式化（:.1f, :.2f）
这是 Python 基础的字符串格式化语法，用于截断浮点数小数位数。
不需要死记，实际做界面时根据显示需求随时翻查即可（如保留两位小数就写 :.2f）。
4. 界面排版、尺寸与美化
如 resize(360, 260)、setWindowTitle(...)、以及控件对齐样式。
绝对不需要手写死记。在实际工程项目中，复杂的上位机控制面板通常使用 Qt Designer 图形化工具直接拖拽布局，导出 .ui 文件后再转为 Python/C++ 调用。
5. 技术选型认知：为什么在这里用 Python Qt 而不是 C++ Qt？
上位机界面通常接收 1Hz 到 10Hz 的轻量级状态广播，Python PyQt 的处理性能完全过剩，且具备免编译、修改立即生效的高效迭代优势。
只有在承载海量高频点云渲染（如 RViz2 插件）、或对微秒级实时响应有极端要求的工业级控制下，才需要深入 C++ Qt。
